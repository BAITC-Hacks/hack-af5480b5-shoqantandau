# AI-агент закупщика

Страница `/agent/` — диалог с OpenAI GPT-5 mini, который выбирает разрешённые инструменты приложения. Количества рассчитывает существующий `engine.py`. Агент не изменяет запасы, не сохраняет, не утверждает и не отправляет заказы.

## Подключение

1. Выполнить `python manage.py migrate`, чтобы создать таблицы учёта расходов.
2. Сохранить ключ в переменной окружения `OPENAI_API_KEY`, в локальном `local_constants.py` или в текстовом файле `.openai-key` в корне проекта. Два последних файла исключены из Git. Не добавлять ключ в репозиторий.
3. Запустить сервер, войти менеджером и открыть «AI-агент». Наблюдатель не может выполнять платные запросы.

На машине разработки ключ уже сохранён локально. Архив и репозиторий ключа не содержат: на другом компьютере нужно подключить собственный.

## Демонстрация

Выберите «ТехноСезон (синтетические данные)». Кнопки примеров заполняют вопрос, затем нажмите «Спросить агента».

- «Проверь риски дефицита. Где нужна закупка, а где достаточно ускорить уже заказанный товар?» Агент получает список рисков; у `3301004_` заказ 0, но склад пуст до прихода 240 штук.
- «Для товара 3301002_ сравни срок поставки 30 дней вместо 20». Ожидаемые расчётные количества: 192 → 228, разница +36.
- Уточните: «А если на складе будет 100 при том же сроке 30 дней?» Результат: 132 штуки, на 96 меньше предыдущего сценария и на 60 меньше стандартного заказа. Эти разницы вычисляет Python; под ответом есть отдельная карточка с числами алгоритма.
- «Сравни вентилятор 1101001_ и конвектор 2201001_ в январе и июле». В сезонных сценариях вентилятор: 80 / 200, конвектор: 180 / 80. Условия сравнения одинаковые; это не календарный план.
- «Найди товары с запасом больше 180 дней». Показывает избыток, включая `3301001_` с остатком 5 000.

Под ответом есть ссылки на карточки, дата данных, модель, расход токенов и раскрываемые результаты вызовов инструментов. Они показывают фактически выполненные действия, а не внутренние рассуждения модели. Можно задавать уточняющие вопросы. Хранятся последние 6 сообщений в серверной сессии; после обновления страницы они видны, но старые карточки инструментов не восстанавливаются. Смена поставщика и «Новый диалог» очищают контекст.

## Инструменты

| Инструмент | Действие |
|---|---|
| find_products | Поиск по коду/названию, до 10 результатов |
| list_risks | Обзор дефицита, избытка или рекомендаций, до 10 позиций |
| get_product | Прогноз, запас, MOQ, срочность, сроки и поставки |
| simulate_product | Пересчёт одного товара с изменением срока, периода заказа, роста, остатка, количества в пути или сезонности |
| compare_seasons | 12 независимых сезонных сценариев по 30 дней |

Сервер сам задаёт поставщика для всех инструментов. Модель не может выбрать чужой источник через аргументы. Используются Responses API, strict schemas и дополнительная серверная проверка. Разрешён только фиксированный набор функций, без SQL, shell, веб-поиска или произвольного кода.

## Расходы и сбои

- Модель фиксирована: `gpt-5-mini`. Оценка по опубликованным ценам $0.25 / млн входных и $2 / млн выходных токенов, включая учитываемые API токены рассуждения. Входные токены считаются без скидки за кэш, поэтому оценка может быть выше фактического списания.
- Локальный бюджет этой функции — $5. Он не ограничивает другие программы, старую кнопку объяснения или весь аккаунт OpenAI.
- Перед запросом атомарно резервируется $0.10; максимум 4 обращения к модели, 6 исполняемых инструментов, 2 000 выходных токенов на обращение и 64 000 байт тела запроса. После ответа резерв заменяется оценкой по usage. При неизвестном результате запроса или падении процесса резерв остаётся учтённым.
- Таблицы AgentBudget и AgentCall хранят бюджет, токены и статус без API-ключа. Одновременные вопросы одного пользователя блокируются на время запроса в текущем процессе.
- API-ошибки показываются без сырых ответов провайдера и секретов. При отсутствии API агент явно сообщает об ошибке; шаблон не выдаётся за ответ модели. Обычные страницы расчёта работают отдельно.

## Данные и ограничения

В OpenAI передаются вопрос, короткий контекст диалога и агрегаты выбранных товаров. Excel-файлы и клиентские ID в инструменты не входят. `store=false` отключает сохранение Responses для последующего обращения по ID; это не обещание нулевого хранения на стороне провайдера.

Агент рассчитывает текущие данные со стандартными настройками. Ручные правки сохранённого заказа не входят в эти ответы. Подмена общего количества в пути использует ближайшую дату поступления, а при неизвестной дате — срок поставки. Имена товаров и текстовые поля считаются недоверенными данными. Ответы модели могут ошибаться: критичные числа проверяйте по результату инструмента и карточке.

Это ограниченный агент для хакатона, а не круглосуточный автономный закупщик. Для нескольких серверных процессов нужен общий rate limiter; локальный лимит бюджета остаётся в базе. Публичное развёртывание требует замены демо-доступов и настройки рабочего сервера.

## Проверка

`python manage.py test procurement` — 63 теста, включая 14 тестов инструментов, API-цикла с подменёнными ответами, прав, бюджета, таймаута и изоляции поставщиков. Дополнительно выполнены настоящие вызовы OpenAI на синтетических данных и проверка чата в браузере. Формулировки модели могут отличаться; числовой результат инструмента воспроизводим.
