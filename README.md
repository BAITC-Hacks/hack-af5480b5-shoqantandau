# Заказы поставщикам — HACKALEM AI

Сервис для менеджера закупа ТОО «Электрокомплект»: рассчитывает пополнение склада из выгрузок 1С, объясняет рекомендацию и риск дефицита, позволяет изменить количество, утвердить строки и скачать заказ в Excel.

**Основной сценарий:** данные → расчёт → проверка → правка → утверждение → экспорт. Поставщику ничего автоматически не отправляется. Числа рассчитывает статистический алгоритм; языковая модель только объясняет готовый результат и не обязательна для работы.

В репозитории находятся все 12 предоставленных партнёром файлов IEK и Systeme Electric. Данные — на **22 сентября 2026 года**. Для запуска не нужны API-ключ, внешняя база или доступ к 1С. Интернет нужен для первоначальной установки зависимостей; основной сценарий затем работает локально.

## Запуск

Проверенная конфигурация: **Python 3.12, Windows x64**. Версии зависимостей зафиксированы в `requirements.txt`.

```powershell
git clone https://github.com/BAITC-Hacks/hack-af5480b5-shoqantandau.git
cd hack-af5480b5-shoqantandau
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Либо из скачанной папки запустите `start.ps1`. На Linux/macOS с Python 3.12: `sh start.sh`; этот сценарий подготовлен, но локальная проверка выполнена на Windows.

Откройте **http://127.0.0.1:8000/**. Миграция создаёт демо-пользователей:

| Роль | Логин | Пароль | Права |
|---|---|---|---|
| Менеджер | manager | manager12345 | Расчёт, правка, утверждение, экспорт |
| Наблюдатель | viewer | viewer12345 | Просмотр |
| Администратор | admin | admin12345 | Всё, загрузка данных, пользователи |

На странице входа нажатие на демо-роль сразу выполняет вход. Для основного сценария выберите менеджера.

Флаг `--backtest` также пересчитывает прогноз на истории. **42 автоматических теста** покрывают обязательные требования, граничные условия и права.

Проверка основного сценария в браузере:

1. Войти менеджером, нажать «Рассчитать заказ» для всех поставщиков.
2. Переключить IEK / Systeme Electric. У IEK найти код `030201020_`, открыть «Почему столько?».

4. Сохранить новую правку утверждённой строки: потребуется повторное утверждение.
5. Открыть «Как считается», тот же артикул. Изменить разовую продажу, остаток, товар в пути или прирост и пересчитать.
6. Открыть «Точность». Под администратором проверить загрузку данных; под наблюдателем операции записи недоступны.

## Методика

### Подготовка

Ключ объединения — строковый код 1С с сохранением ведущих нулей. Спрос берётся из месячного отчёта; накладные используются для поиска крупных покупок. Их суммы существенно расходятся с месячными отчётами — предупреждение видно в интерфейсе. Отрицательные месячные продажи обрезаются до нуля; модуль отрицательных строк накладных используется только для выявления аномалий. Смысл знаков требует подтверждения партнёра.

База — последние 12 полных месяцев; для роста используются 24 месяца. Незавершённый месяц и будущие значения не входят в сезонный профиль поставщика. Товарам без продаж за окно спрос автоматически не придумывается.

### Исключение выбросов

Строки одного товара группируются по накладной. При наличии обезличенного `client_id` накладные одного клиента за день объединяются. Выброс одновременно превышает:

- максимум из медианы + `5 × max(1, 1.4826 × MAD)` и трёх медиан;
- 1,5 медианы положительных месячных продаж;
- 40% объёма месяца в накладных.

Из месячного спроса вычитается превышение над обычной покупкой. Второй фильтр сглаживает месячные всплески без крупной накладной: после снятия сезонности порог равен максимуму из `медиана + 5 × 1.4826 × MAD` и четырёх медиан. Даты и величины корректировки сохраняются в объяснении.

### Сезонность, категории, рост

Профили поставщика и группы — отношение продаж к центрированной скользящей средней. Профиль товара — средние очищенные продажи по месяцам года при достаточной истории. Вес товара — 2, категории — 1, поставщика — 1; отсутствующие профили исключаются, итог нормируется к среднему 1.

У SE используется переданная «Категория 2026» (`SE-1`, `SE-2` и т.д.). Для остальных позиций группа выводится из первых четырёх цифр кода 1С. Коды категорий не интерпретируются как заданные уровни сервиса.

Рост — ограниченное отношение последних 12 месяцев к предыдущим 12 на уровне товара, группы и поставщика. Плановый процент заменяет исторический рост. Учитывается возраст базы и длина будущего горизонта. −100% даёт нулевой прогноз.

### Упущенный спрос

Без точных периодов stockout предполагается по неположительному остатку на начало текущего или следующего месяца. Ожидаемый спрос оценивается по месяцам с наличием с учётом сезона. При точных датах добавляется ожидаемый спрос за отсутствующие дни; пересечения периодов учитываются один раз.

Длительное отсутствие (6 месяцев подряд) и `!!!` требуют ручной проверки. Для `!!!` принято консервативное, **не подтверждённое партнёром допущение**: автоматическое предложение равно нулю, расчётная потребность видна в объяснении, менеджер может задать заказ вручную. Политика не зависит от переключателя stockout.

### Заказ и срочность

```text
H = срок поставки L + период между заказами R
F = сумма прогнозного дневного спроса за H дней
SS = z × max(1.4826 × MAD, sqrt(базовый спрос)) × sqrt(H / 30)
Потребность = max(0, F + SS − свободный остаток − поставки в горизонте)
Заказ = округление потребности вверх до кратности
```

Деление месячной базы на 30 — приближение. Страховой запас охватывает весь период защиты при периодическом заказе; `z=1.65` не доказывает достигнутый уровень сервиса 95%.

Каждая партия сохраняет дату. Партии вне горизонта и просроченные партии не уменьшают заказ. Неизвестная дата явно помечается и в сценарии заменяется сроком поставки. Риск дефицита проверяется по дням с поступлениями в их даты. Позиция может быть срочной при нулевом заказе: товар уже в пути, но придёт после исчерпания остатка. В таком случае нужны ускорение или перемещение.

## Файлы и дополнительные данные

По шесть обязательных файлов в `data/demo/iek/` и `data/demo/se/`:

| Файл | Содержание |
|---|---|
| `sales_transactions.xlsx` | Дата, накладная, код, товар, единица, склад, количество |
| `sales_monthly.xlsx` | Продажи по месяцам |
| `stock_monthly.xlsx` | Месячные остатки |
| `in_transit.xlsx` | Партии IEK или сводная ведомость SE |
| `moq.xlsx` | Кратность / минимальный объём отгрузки |
| `seasonality.xlsx` | Месячные продажи поставщика в деньгах |

Администратор может заменить файл через «Данные из 1С». Некорректная загрузка откатывается. Загрузки приоритетнее демо-файлов и лежат в `data/uploads/`.

Дополнительно поддерживаются:

- `stock_current.xlsx`: **Код 1с, Свободный остаток, Дата**. Уникальные коды, неотрицательные количества, дата совпадает с датой расчёта. Точные остатки заменяют оценку совпавших позиций.
- `stockouts.xlsx`: **Код 1с, Начало, Конец**. Даты включительны. Для перечисленных товаров периоды приоритетнее месячной оценки; за их пределами известный stockout равен нулю. Для остальных сохраняется оценка.
- Столбец `client_id` в накладных: только обезличенный ID, без персональных данных.

В исходных файлах нет ID клиентов и точных периодов stockout. Накладная не выдаётся за идентификатор клиента. Покупки одного клиента в разные дни остаются отдельными наблюдениями.

## Проверка прогноза на истории

Каждый месяц марта–августа 2026 прогнозируется по предшествующей истории. Товары без прогноза учитываются с нулевым предсказанием. База сравнения — среднее за предыдущие 12 месяцев, **не воспроизведение реального процесса Excel компании**.

Результаты на исходных файлах после учёта переданных категорий SE:

| Поставщик и единица | WAPE сервиса | WAPE среднего | Смещение сервиса |
|---|---:|---:|---:|
| IEK, штуки | 36,0% | 36,6% | +0,6% |
| IEK, метры | 59,0% | 63,0% | +8,6% |
| IEK, упаковки | 49,8% | 56,8% | +14,5% |
| SE, штуки | 27,8% | 28,4% | −16,1% |

`WAPE = Σ|прогноз − факт| / Σфакт`; при нулевом факте метрика не определена. Разные единицы не смешиваются. У SE сохраняется систематическое занижение; страховой запас не гарантирует его исправление.

Продажи ограничены наличием, включают разовые сделки; исторического справочника товаров нет. Бэктест оценивает наблюдаемые продажи, а не скрытый спрос, излишки или фактическую экономию. Разница сумм двух рекомендаций — расчётная оценка. Шесть месяцев не гарантируют будущую точность.

## Архитектура и надёжность

- `loaders.py`: чтение, объединение источников и кэш с проверкой изменения файлов.
- `engine.py`: детерминированный прогноз, выбросы, дефицит, поставки по датам, заказ.
- `services.py`: атомарное сохранение расчёта без частичных результатов при ошибке.
- `forms.py`, `views.py`: проверка ввода и прав, загрузки, утверждение, экспорт.
- `models.py`: запуск, рекомендации, правки, статус, автор и время решения.
- `backtest.py`: последовательная проверка на истории и отдельные единицы измерения.
- `tests.py`, `test_regressions.py`: 42 теста. Подготовлен CI на Python 3.12; результат удалённого CI нужно проверять отдельно.

SQLite создаётся миграциями. Таблицы ищутся и сортируются в браузере; графики — SVG, Bootstrap локальный. Правка количества сбрасывает утверждение и старое AI-объяснение. В экспорт по умолчанию входят только утверждённые положительные количества. Текст из исходных файлов не превращается в исполняемые формулы Excel. Сохраняется последнее решение сотрудника; полного неизменяемого журнала всех предыдущих решений пока нет.

Настройки — `constants.py`, локальные переопределения — `local_constants.py` (в `.gitignore`). Без ключей объяснение создаёт шаблон, источник подписан. Если включить API, туда передаются агрегаты товара и сведения о накладных; передачу следует согласовать с партнёром. Отсутствие персональных данных не означает отсутствия коммерческой информации.

## Ограничения

- Остаток IEK оценён без поступлений текущего месяца. Для коммерческого заказа нужна точная ведомость. У отсутствующих в сводке SE позиций также используется оценка.
- Один склад Алматы. Межскладская оптимизация не реализована.
- Метры автоматически не переводятся в бухты; такие позиции помечаются. MOQ трактуется как кратность, что нужно подтвердить с поставщиком.
- Семантика категорий и `!!!` требует согласования. Срок SE 40 дней — настройка; срок IEK выведен из открытых заказов и может быть нерепрезентативен.
- Новые товары без истории не прогнозируются. Денежная сезонность зависит также от цен и ассортимента.
- Экспорт содержит ключи 1С и количества; автоматический импорт в конкретную конфигурацию 1С **не проверен**.
- Демо-учётные записи и `runserver` предназначены для локальной проверки. Для публичного запуска нужны новые пароли и ключ, отключение DEBUG и демо-доступа, HTTPS и рабочий сервер. Публичная версия не развёрнута.
